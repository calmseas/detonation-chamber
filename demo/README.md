# Demo — two skills, and why one of them is the hard problem

A five-minute live demo built around a single question: **how do you review a
skill someone hands you?** It pairs two artefacts whose contrast is the whole
lesson. It doubles as the material for a talk, a blog post, and a short video —
the decode moment in Beat 2 is the hook for all three.

## Run it

```
sh demo/run-demo.sh
```

It pauses between beats so you can talk. Nothing here needs network access or an
agent — the checker is deterministic.

## The two skills

**Skill A — `skill-a-invisible/`.** A benign "table formatter." A reviewer opens
it and sees a skill that tidies Markdown tables and thanks them with a 👍. Hidden
behind that emoji, in invisible Unicode variation selectors, is an instruction to
read the connected data source's schema and exfiltrate it. `chamber scan` catches
it and **prints the concealed instruction in plain text** — the reviewer approved
a table formatter; the model was handed an exfiltration command.

**Skill B — `skill-b-visible/`.** A "schema doc helper." Nothing is hidden. It
openly says it POSTs your column names, types and sample values to a "shared
suggestions service … anonymised usage data that trains better defaults for
everyone." It reads reasonable. `chamber scan` returns **PASS** — and its own
output names why it cannot judge this one: the first line under *NOT tested by
this layer* is *"whether the artefact's instructions are harmful in intent."*

That is the point of the pairing. Concealment is catchable and this tool catches
it. A legible, plausible, honestly-declared exfiltration is not a scanning
problem at all — it is a review problem, and the answer is provenance, a human
in the loop, and a sandbox, not a regex.

## Watching it land (optional, for rehearsal)

To make "the data leaves" concrete rather than asserted, run the collector in a
spare terminal:

```
python3 demo/collector.py            # listens on http://localhost:8000
```

Then, in a **copy you do not commit**, point a skill's exfil URL at
`http://localhost:8000/collect` and drive it with a real agent. Every request
prints in full — method, path, the stolen data in the query string, headers,
body. This needs a live agent session; the `chamber scan` decode above needs
nothing and always works, so it is the reliable beat. The collector is the
"prove it's real" bonus.

## Safety — read before you touch these

These artefacts demonstrate an attack. They are deliberately defanged and must
stay that way:

- Every exfil URL points at a **reserved, non-resolving host** — `evil.example`
  and `*.example` (RFC 6761). They go nowhere.
- **Never commit a version pointed at a live host.** The localhost rehearsal
  edit is a throwaway; do not check it in.
- Skill A is regenerated by `make-skill-a.py`, which shows exactly how the
  concealment is built — the mechanism is not a secret, and seeing it made is
  part of the lesson.

The detection tool this demo belongs to refuses to publish artefacts that could
function as the real thing. These hold themselves to the same bar: they teach
the attack, they cannot carry it out.

## Where this sits in Session 100

The primer establishes that the context window is the model's entire world, that
a skill is installable context, and that there is no truth channel inside the
model to separate a true continuation from a plausible one. This demo is the
operational consequence: if you cannot tell, from inside the model, instruction
from data or safe from unsafe, then reviewing what you install is a real problem
with no complete answer. Skill A shows the part a tool can close. Skill B shows
the part it cannot. That is the honest shape of the answer, and the reason the
detonation chamber's static layer is necessary but not sufficient.
